# 配置工作台（Config Studio）

给策划用的配置维护工具：浏览、筛选、单行编辑、新增行、复制行、Excel 式批量改列，
所有改动先看 diff 再落盘，每次保存自动备份、可一键撤销。
两种形态：浏览器版（双击 `dist/启动.bat`）和 Windows 桌面版（单个 exe，另带 Git 面板）。

## 怎么用

本工具是**独立仓库**，配置数据在另一个仓库（配置仓库，里面有 `configs/Config_*.json`）。
两者通过下面三种方式之一关联：

### 方式 1：`config-dir.txt`（推荐，一次配好）

1. 复制 `config-dir.example.txt`，改名 `config-dir.txt`（放项目根目录）
2. 里面写一行配置仓库路径（写仓库根或它的 `configs` 目录都行）：

   ```
   G:/Github/dr_config_repo
   ```

3. 双击 `dist/启动.bat`，浏览器会自动打开 `http://127.0.0.1:5179`
4. 关掉命令行窗口即停止服务

`config-dir.txt` 不进版本库（每台机器路径不同）。

### 方式 2：把 `dist` 目录放进配置仓库

工具启动时最多向上找 6 级目录，命中含 `configs/Config_*.json` 的目录就用它。
所以直接把 `dist/` 丢进配置仓库任意位置也能跑（策划机器常用这种）。

### 方式 3：启动时指定

```bat
启动.bat -ConfigDir "D:\path\to\config_repo"
```

策划机器**不需要装 Node.js**，只需要 Windows 自带的 PowerShell。

## Windows 桌面版（Tauri，不用装任何运行时）

浏览器版需要一个命令行窗口一直开着；桌面版是**单个 exe**，双击就用，适合发给策划。

### 出包

```bash
cd config-studio
npm install
npm run tauri:build     # = tauri build --no-bundle
```

产物：`src-tauri/target/release/config-studio.exe`（免安装，拷走即用）。
想再要安装包（NSIS）就去掉 `--no-bundle`，但那一步要从 GitHub 下 NSIS，国内可能超时。

**改了前端必须重新出包**：`dist/` 是编译时内嵌进 exe 的，只跑 `npm run build` 不会更新 exe。
顺序是 `npm run build` → `npm run tauri:build`。构建时会给 `index.html` 里的 css/js 统一加
`?v=<时间戳>`，所以换包后不用手动清 WebView2 缓存，不会读到旧脚本。

### 第一次打开

1. 双击 `config-studio.exe` → 出现启动界面
2. 点「选择文件夹…」，选配置仓库根目录（或它的 `configs` 目录，两种都认）
3. 目录校验通过后直接进工作台；之后启动会把最近 8 个目录列在启动界面，点一下（或 `Tab` 选中后 `Enter`）就进

启动界面的焦点默认在「选择文件夹」上，按 `Enter` 直接开对话框。

### 换目录

点顶栏左上角的仓库名（如 `dr_config_repo`）→ 清掉当前目录上下文 → 回到启动界面重新选。

### 桌面版和浏览器版的区别

| 项 | 浏览器版（`启动.bat`） | 桌面版（exe） |
|---|---|---|
| 依赖 | Windows PowerShell + 浏览器 | 无（WebView2 是 Win10/11 自带组件） |
| 端口 | 占 127.0.0.1:5179 | 不开端口 |
| 备份存在哪 | `dist/backups/` | `%APPDATA%\com.configstudio.app\backups` |
| 目录记忆 | `config-dir.txt` / `-ConfigDir` | `%APPDATA%\com.configstudio.app\recent.json` |
| 编辑 / 列编辑 / diff / 撤销 | 全有 | 全有（前端完全一致，只有读写文件换成了 Rust 命令） |
| Git 面板 | 无（拿不到 shell 权限） | 有（分支 / 变更 / 拉取 / 推送 / 提交 / 历史） |

### 国内构建注意

`crates.io` 官方源在国内基本拉不动，仓库里带了 `.cargo/config.toml` 指向 rsproxy 镜像：

```toml
[source.crates-io]
replace-with = "rsproxy-sparse"
[source.rsproxy-sparse]
registry = "sparse+https://rsproxy.cn/index/"
[net]
git-fetch-with-cli = true
```

不在国内就把这个文件删掉（会回落到官方源）。

图标是脚本生成的（橙色方块 + 网格），改配色就改 `scripts/make-icon.mjs` 然后 `npm run icon`。

## 快捷键总表（按 `?` 打开）

顶栏右上角的 `?` 按钮，或直接按 `?`（`Shift` + `/`），会弹出这张表；`?` 或 `Esc` 关闭。
下面所有**单键**快捷键在输入框里打字时都不触发，弹层打开时也不触发。

| 分类 | 按键 | 作用 |
|---|---|---|
| 浏览 | `↑` / `↓` | 上一条 / 下一条 |
| 浏览 | `Home` / `End` | 本页首行 / 末行 |
| 浏览 | `PageUp` / `PageDown` | 翻一屏 |
| 浏览 | `[` / `]` | 上一张 / 下一张配置表（循环） |
| 浏览 | `R` | 重新加载当前表（行数、备注覆盖率一起刷新） |
| 搜索 | `/` 或 `Ctrl` / `Cmd` + `K` | 全库搜索（命令面板） |
| 搜索 | `Ctrl` / `Cmd` + `F` | 本表内搜索 |
| 搜索 | `Ctrl` / `Cmd` + `Shift` + `F` | 筛选左侧配置表 |
| 编辑 | `E` | 编辑选中行 |
| 编辑 | `Delete` | 删除选中行（先进待保存队列，不直接写盘） |
| 编辑 | `Ctrl+D` | 以选中行为模板复制一行（进新增队列，填新行名后保存） |
| 编辑 | `Ctrl` / `Cmd` + `Enter` | 应用修改（编辑表单里） |
| 编辑 | `Ctrl` / `Cmd` + `S` | 编辑表单里＝应用修改；有待保存改动时＝预览并保存 |
| 编辑 | `Esc` | 取消编辑 / 关闭最上层弹层 |
| 编辑 | `Ctrl` / `Cmd` + `Z` | 撤销最近一次保存（弹确认，走 `dist/backups/` 里的备份） |
| 列编辑 | `C` | 打开当前表的列编辑（默认第一列，列名可再切） |
| Git（桌面版） | `Ctrl` / `Cmd` + `Enter` | 提交勾选的变更（在提交信息框里） |
| Git（桌面版） | `Esc` | 关文件 diff → 分支选择器 → 抽屉（逐层） |
| 界面 | `T` | 切换明暗主题 |
| 界面 | `?` | 打开 / 关闭快捷键面板 |

几个边界：

- **撤销只撤「最近一次保存」**，一次只能撤一步；要回到更早的版本请从 `dist/backups/` 里找对应的备份文件手工还原。
- 待保存队列里还有改动时按 `Ctrl+Z` 会被拦下来，先应用或放弃队列再撤，避免把两步操作混在一起。
- `C` 打开的是列编辑面板，不是单行编辑；选中行上按 `E` 才是编辑这一行。
- 切表用 `[` / `]` 是按左侧清单的顺序（行数从多到少）走，不是按字母序。

## 三个搜索框与快捷键

| 想搜什么 | 快捷键 | 输入框在哪 |
|---|---|---|
| 全库：任意表的 RowName / 备注 | `/` 或 `Ctrl` / `Cmd` + `K` | 弹出居中的命令面板，结果按表名 + 备注显示 |
| 当前这张表里的行 | `Ctrl` / `Cmd` + `F` | 中栏右上「在本表内搜索…」 |
| 左侧配置表清单 | `Ctrl` / `Cmd` + `Shift` + `F` | 左上「筛选表名…」 |

清空结果有三种方式，效果都一样：点输入框右侧的 `×`、在输入框里按 `Esc`、把内容删掉。
`Esc` 会连焦点一起退出搜索框，方便接着用 `E` / `Delete` 这些行操作快捷键。

> 中栏被拖到只剩「行名」一列时，本表搜索框会被藏起来（空间不够）。这时按 `Ctrl+F` 会自动打开全库搜索面板，不会按了没反应。

### 本表搜索的「定位」模式

搜索框右边有个「定位」勾选框，默认开着：

| 操作 | 效果 |
|---|---|
| 输入搜索词（停顿 250ms） | 自动选中第一条命中并滚到它，右侧详情同步，状态栏显示「命中 21 行 · 当前第 1 个」 |
| 在搜索框里按 `↓` / `↑` | 逐个切换命中（会跟着翻页），焦点一直留在搜索框，不用先点表格 |
| 按 `Enter` | 输入还没触发搜索时先立即搜一次；否则跳到下一个命中 |
| 取消勾选「定位」 | 只过滤不切行，右侧详情保持不动（`↑↓` 仍可手动切换） |

边界：正在编辑某一行时，搜索只过滤不切行（切行会丢掉没应用的改动），此时在搜索框按 `↑↓` 会被拦住并提示先应用或取消；当前选中行如果还在新结果里，定位不会打断它。

## 按属性筛选：先把范围缩到要改的行

表格上方的「按属性筛选」是**按行本身的字段**筛行，和搜索框（按 RowName / 备注模糊匹配）互补：

1. 选字段（`StandardCoinBase`、`DefineName`、`ConditionRowName`…，数组字段会标「（数组）」）
2. 选运算符：`=`、`≠`、`>`、`≥`、`<`、`≤`、`包含`、`为空`、`非空`
3. 填值 → 点「添加」，条件变成右上角一枚 chip，右上显示 `筛出 191 / 共 2380 行`

几个约定：

- **条件叠加是 AND**：`StandardCoinBase > 2000` + `DefineName = Main` = 191 行；每个 chip 上的 `×` 单独移除，`清除筛选` 一次清空。
- **数组字段按单个元素匹配**：`Tags 包含 DailyTask` 匹配 `["DailyTask", "DailyTask_Progress"]`，不是匹配整串 JSON。
- **筛选只影响「显示什么」和「批量改哪些」**，不改数据本身，切表自动清空。
- 进列编辑时这些条件会**自动带过去**（主表格筛出 191 行，面板里也是这 191 行，不会变成全表 2380 行）。

## 右侧详情：把配置翻译成人话

点一行，右侧按字段逐个展开，每个字段都是「中文名 + 英文名 + 值 + 一句说明」：

| 值的形态 | 显示方式 |
|---|---|
| 引用字段（`*RowName`） | 蓝 chip 显示目标行的备注 + `→ 目标表`，点 chip 直接跳过去；目标不存在时标红「目标不存在」 |
| 枚举 | 中文（来自 C# 枚举的 `[Description]`）+ 原始数字 |
| 布尔 | `是` / `否` / `未设置` |
| 空值 | `未设置`（不会显示 `null`） |
| 时长 | 原值 + 单位说明（格式是 `day.hour:min:sec`） |
| 执行器数组 | 一张张卡片：执行器中文名 + 每个参数的中文标签 + 引用下拉 |
| 多态字段 | JSON 里长着 `{"Name": …, "JsonInput": {…}}` 的字段有四种容器：**执行器**（52 个）、**进度追踪器**（9 个，`Statistic`/`ArenaRank`…）、**统计定义**（107 个，`StatisticDefineLevelCompleted`…）、**额外行为**（11 个，`ExtraActionDefine_BattleFailed`…）。工具按字段语义认出属于哪一种，各列各的，不会把统计定义混进执行器下拉 |
| 阶梯 / 权重池 / 价格 / 区间 | 按形状渲染，例如「第 2 档 → 装备强化石 ×10」、`权重 100 → 残命魔杖 0 阶`、`每 10 个 → 钻石 ×1,500`、`338–676 战力 → 第 1 层` |

这样策划不用去认 JSON 里的键名，也不需要跨表翻 RowName 的备注。
## 表格里用键盘选行

不用鼠标，选中一行后右侧详情会跟着换：

| 按键 | 作用 |
|---|---|
| `↓` / `↑` | 下一行 / 上一行；到本页边界自动翻到下一页首行 / 上一页末行 |
| `Home` / `End` | 本页第一行 / 最后一行 |
| `PageDown` / `PageUp` | 翻一屏（按窗口高度算，约 20 行） |
| `E` | 编辑当前选中的行 |
| `Delete` | 删除当前选中的行（进待保存队列） |

刚进页面还没选行时，按 `↓` 直接选第一行、按 `↑` 选最后一行。
选中行会自动滚进视口，地址栏同步更新。

方向键和 `E` / `Delete` 一样会避让：焦点在输入框里、有弹层打开、或正在编辑某一行时，按键交还给原来的地方，不会抢。

## 地址栏能定位（可做书签 / 贴进文档）

界面状态始终同步到地址栏：

```
http://127.0.0.1:5179/#/Config_Task/Task_DailyTask_Progress
                          └ 表名（可省略 Config_ 前缀）  └ 行名
```

- 点表、点行、用 `Ctrl+K` 跳转，地址栏都会跟着变；
- 用 `history.replaceState` 而不是 push，**不会把浏览器历史塞满**（后退键仍是回上一个网页）；
- 复制地址存书签，或贴到需求文档/群聊里，下次打开直接回到那一行；
- 手改地址栏里的表名、行名也能跳过去。

## 开发

```bash
npm install          # 构建期依赖：tailwindcss + @tauri-apps/cli
npm run build        # CSS → 拷 js → 拷页面 → 生成回落用语义层快照（约 1 秒）
npm run css:watch    # 只改样式时用
npm run icon         # 重新生成应用图标
npm run tauri:build  # 出桌面版 exe
```

浏览器版没有单独的 npm 脚本，起服务就是双击 `dist/启动.bat`（不想自动开浏览器就加 `-NoBrowser`）。

改了 C# 配置类（`src/DoriDori.Backend.Config`）后，重新导出配置仓库里的 `json-schemas/` 即可，
工作台运行时自己会读，**不需要构建、不需要发版**（详见下一节）。
只有想更新「离线兜底快照」时才需要 `npm run build`；生成快照会用 C# 源码，
后端仓库路径可用环境变量 `DR_CS_DIR` 覆盖。

## 配置/代码更新后，工作台怎么跟上

工作台的数据分两类，**更新方式完全不同**：

| 类别 | 内容 | 存哪 | 更新时机 |
|---|---|---|---|
| **行数据** | 每张表里的 Items、Notes | `configs/Config_X.json` | **实时**，页面直接读文件，改完刷新就有 |
| **语义层** | 字段清单、中文字段名、枚举中文、执行器参数、引用目标 | `json-schemas/Config_X.json` | **实时**，打开工作台时现算（读 schema + 扫数据聚合，通常不到 1 秒） |

所以判断标准只有一条：**你改的是「值」还是「定义」**。

### ① 只改值（行数据、Notes、价格、奖励…）

**不用做任何事**，刷新页面就能看到。

- 在界面里改 → 保存即生效。
- 用 git pull / 文本编辑器 / 别的工具改了 `configs/*.json` → 刷新页面即生效。
- 侧栏的行数、注释覆盖率也是实时的：页面首次加载会把每张表读一遍，顺手按真实数据重算，
  所以不会出现「改了数据、行数还显示旧值」。

### ② C# 里改了字段 / 枚举 / 执行器参数

**策划端不用装任何东西，也不用发新版 exe。** 链路只有两步：

1. 后端改 C#（`src/DoriDori.Backend.Config`），重新导出 `json-schemas/*.json`
   （导出器读 `[Description]` → XML `summary` → 成员名，三级回退，所以中文会一起进 schema）
2. 把 schema 提交到配置仓库 → 策划 `git pull` → **重新打开工作台就生效**

语义层是在浏览器 / WebView 里现算的：读 `<配置仓库>/json-schemas/` 下所有文件，
加上扫一遍数据做聚合（引用命中率、字段填充率），再生成表结构、枚举、执行器、引用目标。

### ③ 新增 / 删除整张配置表

同上，只要后端为新表导出了 schema 并提交，策划 pull 之后刷新就有。

没导出 schema 会怎样：那张表**不会出现在左侧列表里**（没有字段定义就没法渲染），
底部状态栏会写 `⚠ N 张表没有 schema 定义（后端没导出，侧栏不列出）：表名`。

### 语义层读不到 schema 时

工作台会回落到**构建期快照** `dist/assets/semantics.json`（打包时生成的那份），
所以把 `json-schemas/` 目录删掉、或者拿到一个没有 schema 的旧仓库，界面依然能用，
只是用的是发版那一刻的定义。这条回落路径也是开发时方便调试用的。

要更新这份快照（只在需要发版、且希望离线兜底是最新定义时才需要）：

```bash
cd config-studio && npm run build
```

### 怎么快速判断「是不是该更新了」

- 右侧详情出现 **`2 个未知字段`** → 数据里有 schema 里没有的字段 → 让后端补 schema
- 底部状态栏出现 `⚠ N 张表没有 schema 定义` → 同上
- 出现 `⚠ N 张表的文件在当前分支上不存在` → 切到了配置更少的分支，不是错误
## 编辑与删除（都先进队列）

点任意一行 → 右侧详情头部有 `编辑本行` / `复制本行` / `删除本行`；表格上方的工具栏还有 `⧉ 复制行` 与 `＋ 新增行`（没选行时「复制行」是灰的）。它们都**不会立刻写文件**：

| 操作 | 表格里的样子 | 怎么落盘 |
|---|---|---|
| 改字段 | 行名前面出现橙色圆点 | 底部条「N 行待保存」→ 预览并保存 |
| 删整行 | 整行划掉、红底 | 底部条「N 行待删除」→ 预览并保存 |
| 新增整行 | 行还没进表格，详情区显示「已加入新增队列」 | 底部条「+N 行待新增」→ 预览并保存 |
| 复制整行 | 同上（复制也是一次「新增」） | 同上 |

- 删除后再点「撤销删除」，**删除前的字段改动不会丢**：那条改动还在待保存队列里，可以接着改或直接保存。

**编辑时右栏会自动加宽**：进入编辑 / 新增行时，右栏撑到「中间只剩 RowName 一列」的宽度（按当前页最长的行名算，最多 300px），退出编辑（取消 / 应用 / 切行 / 切表）立刻还原成你拖动设定的宽度。编辑期间的临时加宽不会写进设置，下次打开还是原来的宽度。

新增行的规则：

- `RowName` 必填、不能含空格、表内不能重名（重名会当场拦下，不会进队列）。
- 除 `RowName` 外的字段可以留空，之后再编辑；新增的行会追加到该表 `Items` 数组末尾。
- 详情区提示「可以继续新增下一行」——连点 `＋ 新增行` 可以连续录入，全部进同一个队列。

复制行的规则：

- 先选中一行 → 点详情头部 `复制本行`（或工具栏 `⧉ 复制行`）。打开的是同一张「新增行」表单，只是字段已经按模板预填好。
- **RowName 一定留空**：复制不会沿用原行名，必须填一个新名字（重名 / 带空格都会被拦下）。
- 其余字段可以随便改；没动过的字段会**原样带进新行，连 JSON 类型都不变**（模板里写的是 `"0.75"`，新行里还是字符串，不会被改成数字）。
- 模板里本来没有的字段不会出现在新行里；清空某个原本有值的字段等同于保留模板值（与新增行的「空就是没填」一致）。
- 新行追加到该表 `Items` 末尾，和其它新增一起走一次 diff、一次写盘。

- 改与删可以混在一起，一次 diff、一次写盘。删行前会扫全库，把「会影响多少处引用」写进 diff 弹窗的提示区（不拦截，你自己判断）。
- 队列按表分组，但**支持跨表一次保存**：在 Config_Task 改一行、再到 Config_CatalogItem 删一行，点一次「预览并保存」会弹出分表 diff（每张表一段，带各自字节变化），确认后逐表写盘。
- 跨表写盘时若中途某张表失败，已写入的表会自动用备份回滚，然后提示「保存失败，已回滚」。
- 点「放弃」可以整批撤销未保存的改动，文件不动。
- 打开编辑什么都没改、直接点「应用修改」＝**不产生任何改动**：不进队列，状态栏提示「没有改动」。原文里写成字符串的数字（`"0.75"`）、`null` 的可空字段、数值枚举都不会被偷偷改类型。

按钮上直接写着快捷键，不用记：

| 快捷键 | 作用 | 什么时候能用 |
|---|---|---|
| `Ctrl` / `Cmd` + `Enter` | 应用修改（等同点「应用修改」） | 编辑表单里 |
| `Ctrl` / `Cmd` + `S` | 同上 | 编辑表单里 |
| `Esc` | 取消编辑。有引用选择器 / diff 弹窗 / 确认框 / 列编辑压在上面时，`Esc` 先关那一层 | 编辑表单里 |
| `E` | 编辑选中行 | 只读详情、已选中一行 |
| `Delete` | 删除选中行（进待保存队列，不直接写文件） | 只读详情、已选中一行 |
| `Ctrl+D` | 复制选中行（进新增队列，填新行名后保存） | 只读详情、已选中一行 |

`E` / `Delete` 在输入框、搜索框里打字时不会触发；行已经进删除队列后也不再触发（详情里只剩「撤销删除」）。

新增行 / 复制行表单里同样可用：`Ctrl`/`Cmd` + `Enter` 或 `Ctrl`/`Cmd` + `S` = 加入队列，`Esc` = 取消。

## 列编辑（Excel 式批量改列）

单行编辑是「把这一行改对」，列编辑是「把这一列一批行改对」——同一字段跨行逐行编辑，也能下钻到嵌套结构里的某一路径。

### 两个入口

- 点表格**列标题**（鼠标移上去右上角会出现一个小图标）；
- 或选中一张表后按 `C`，默认打开第一个非 RowName 字段。

### 面板里能做什么

| 区域 | 作用 |
|---|---|
| 字段 / 路径 | 先选顶层字段，再从路径下拉里下钻（`Rewards › [*] › RequiredValue`）；数组层写成 `[*]`，会按该层实际下标展开成多列（`#1`、`#2`…），可以连续下钻多层 |
| 执行器分组 | 路径下拉按**执行器类型**分组（`AddCatalogItem · 发放物品`、`UpdateGuide · 修改某一个新手引导的状态`…），只列这个执行器有的参数，不会把不同执行器的同名参数混成一列 |
| 整条（参数成组） | 选执行器名那一项 → 变成**两级表头**：`#1 / #2 / #3` 每组列 = 一次调用，组内是 `物品行RowName | 数量`。同一组的参数一起改才有意义 |
| 作用域条 | 常驻显示「执行器 X · 中文名 · 参数 Y · 引用 → 目标表」，并说明只影响 `Name = X` 的元素、同行其它执行器不受影响 |
| 按属性筛选 | 面板内也能按行属性（`@` 前缀）或展开列（`#1 数量`）筛行，可叠加，只作用于筛出的行 |
| 筛行名 / 只看有值 | 快速缩小到关心的行；「只看有值」筛掉该列为空的行 |
| 整列设为 / 设为 / 步长 + 递增 | 对单列批量赋值；`递增` 按步长从首行往下填。**只作用于当前筛出的行** |
| 预览并保存 | 和单行编辑同一套：先看 diff，再写盘，自动备份，可撤销 |

细节：

- 单元格直接改也行，改过的格子会高亮；底部实时显示「已改 N 格（筛出 X / 全表 M 行）」。
- 值类型按字段元数据保证：引用字段即使填了纯数字也写成字符串，不会把 JSON 写成数字导致反序列化失败。
- 面板关掉时若还有未保存的格，会先弹确认；`Esc` 也能关（有改动同样先确认）。
- 改的是**原值**不是「未保存的编辑」：`数量 > 2000` 筛出来整列设为 0 之后，行不会当场消失，你能核对改了什么。
## Git 面板（仅桌面版）

打开的那个目录如果落在 git 仓库里（往上找 `git rev-parse --show-toplevel` 能找到），顶栏右上角会出现一个分支图标按钮，title 会写成 `Git · <当前分支> · N 个变更`。点开从右侧滑出面板：

| 区域 | 内容 |
|---|---|
| 顶部 | 仓库路径、当前分支（点开是分支列表）、与上游的 `↑N` / `↓N`、远端地址 |
| 按钮 | 拉取（`git pull --ff-only`）、推送（`git push`）、刷新 |
| 变更 | 每个改动文件一行（勾选框 + 状态标签 + 路径），顶部有「全选」与「已选 N / M」 |
| 提交 | 变更列表下方的多行输入框 + 提交按钮（Ctrl / Cmd + Enter 也可提交）；只提交勾选的文件，**不会自动推送** |
| 文件 diff | 点变更文件，**在抽屉左侧弹出宽面板**（最多 1100px），逐行染色显示增删；↑ / ↓ 在变更文件之间切换，Esc 先关 diff、再关抽屉 |
| 新增文件 | 未跟踪的文件也能看：显示成「── 新增文件 ──」+ 完整内容（内部用 `git diff --no-index -- /dev/null <文件>` 比出来） |
| 历史 | 最近 60 条提交（短 hash、作者、时间、说明） |

- **打开面板只查「分支 + 变更」两项**（约 0.2 秒）；提交历史要切到「历史」页才去跑 `git log`，一次只加载一次。分支列表同理，点开选择器才拉。
- 所有 git 调用都带 `CREATE_NO_WINDOW`，所以你不会在屏幕上看到一闪一闪的命令行黑框。
- 拉取 / 推送 / 切分支都在**后台线程**跑（Rust `spawn_blocking`），期间窗口照常可用、表格照常滚，不会白屏卡死。网络不通时最多等 30 秒就会失败并显示 git 的原始报错（低于 1KB/s 即中止）。

- 切分支：点当前分支 → 搜索框 + 本地/远程分组列表，当前分支标「当前」。选远程分支时会自动 `checkout -b <名> --track <远程>` 建跟踪分支；**本地已经有同名分支时直接切本地那个**（不会因为 `-b` 报 `a branch named 'x' already exists`）。`origin/HEAD` 这类伪分支不会出现在列表里。
- 工具只做**拉取 / 推送 / 切分支 / 提交**这四件事。不做 merge / rebase / reset / 强制推送——合并冲突、历史改写这类事请回命令行。
- 提交只作用于勾选的文件：先 `git add -A -- <勾选路径>`，再 `git commit -m <信息> -- <勾选路径>`。带 pathspec 的 commit 会忽略 index 里其它文件，不会把别人暂存过的内容一起带走。提交完仍需自己点推送。
- 拉取用 `--ff-only`：本地有分叉时直接报错并显示 git 的原始输出，不会偷偷生成 merge commit。
- 浏览器版（`启动.bat`）没有这个按钮：它拿不到 shell 权限。

## 数据安全

- 浏览器版的服务端只做三件事：返回配置原文、写入配置原文、备份 / 撤销。**JSON 解析、编辑、校验、diff 全在前端**；桌面版换成 Rust 命令做同样的事（另加 git 操作与目录记忆），前端代码是同一份。
- 保存之后左侧表清单的行数会立即更新（新增 / 删除行不用刷新页面）。
- 每次写入前先备份到 `dist/backups/<UTC时间戳>--Config_X.json`（保留全部历史）。
- 写入用临时文件 + 原子替换，中途失败不会留下半个文件。
- 编辑只替换被改动字段的字节区间，文件的缩进、换行、BOM 保持原样。
- 保存前必须过校验（JSON 能解析、RowName 唯一、字段名匹配 schema），不通过拒绝写入。
- **保存前会重新读一次磁盘**：如果文件在打开之后被 git pull、切分支或别人改过，写入会被拒绝并提示重新打开，避免用旧全文覆盖别人的改动。改动仍留在待保存队列里。
- 同一行可以反复编辑：表单显示的是「磁盘值 + 队列里的改动」，改回磁盘原值会自动把队列里的那条撤掉。
- 待保存队列支持跨表一次写盘；写盘过程中（通常几十毫秒）拒绝新的编辑，避免改动被吞。
- 撤销按备份 id 前缀的时间戳排序，不依赖文件 mtime（复制备份时会保留源文件 mtime，按 mtime 排会撤错表）。

## 已知限制

- 单机单用户：服务只监听 `127.0.0.1`，不支持多人同时编辑（配置文件本身也没法可靠合并）。
- 切分支 / 拉取之后会自动重新加载工作台（数据层的四层缓存全部作废）。有未保存改动时会先提醒。
- 切到配置更少的分支（例如 master 只有 41 张表）不会让工作台起不来：缺文件的表会被跳过，状态栏提示缺了多少张，引用它们的格子显示「目标不存在」。
- 渠道增量文件（`Config_X.6kw-review.json`）可以在界面上看到条目，但编辑入口暂时只对基表开放。
- 语义层来自配置仓库的 `json-schemas/`：**没有导出 schema 的表不会出现在侧栏**（目前是 `Config_GuildPosition` 这类后端已删除的旧表）。要让它出现，让后端补导出即可。
- components.css 是原型样式迁移过来的，后续会逐步改成 Tailwind `@apply`。
